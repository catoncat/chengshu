# 叠物桌：重做核心交互，不给流程表换卡面

用户明确否定了上一版「能力卡盒」：它是一张向用户汇报设计的演示页，不是游戏式交互，也不是产品级成果。该反馈覆盖此前助手对旧稿的自我评价。

本目录是独立实验，不替换 Android App，不修改现有产品开发状态，不发布 APK。没有通过真实用户体验评审，不宣称达到产品级。

## 先试，不用读方案

打开 `index.html`。单文件，无依赖、无外部请求；支持桌面鼠标和手机触摸。不能在 GitHub 源码预览里直接运行，需要以 HTML 在浏览器打开，或从本目录启动任意本地静态服务器。

桌上有一篇项目自制 HTML 和一张项目自制配色图。拖「净文」到文章，得到实际文字；拖「装订」到文字，得到真实 EPUB；从图片「取色」，把色笺叠到书上改变封面；最后用「留档」请求浏览器下载文件。原件不消耗，撤回可用。

也能放入自己的 TXT、Markdown、HTML、PNG/JPEG/WebP；两份文页叠成文集；把已完成的线性做法收成配方，换另一份素材再用；配方可导入/导出 JSON，只接受已定义操作，不执行任意插件代码。

## 这次到底改了什么

删掉侧栏、设计说明、输入输出配置栏、执行按钮、假社区、模拟失败和按秒播放的进度。现在牌是在桌面上存在的物件，而不是配置项：拿起、靠近、吸附提示、松手、产生新物件、再组合。不能组合时保留原件、给局部反馈；没有靠长篇文案解释每一步。

桌面只留下一个首次动作提示。手艺牌可复用；素材是真实内容；成果可翻开、下载、收成可重复执行的做法。取色后的色笺还能用于另一条分支的书封面，用同一套叠放规则形成新的用途。

## 明确边界

- 仍是需要用户判断手感的交互实验，不是完整游戏或产品发布。
- 本地 HTML 净文采用保守的 DOM 文本清理，不是生产级网页正文提取；只取文字，HTML 内图片不打包。
- Markdown 按文字处理；没有语义级 Markdown 排版、网页抓取、录音转写、AI、社区安装或阅读器交接。
- 图片导入保存缩放副本，原始文件不变；颜色从实际像素提取，不是固定样例结果。
- EPUB 使用本地 ZIP/XML 生成，封面颜色与文字是真实内容。测试验证实际下载文件的 ZIP CRC、XML 与正文；没有运行 EPUBCheck 或真实阅读器。
- 桌面存在浏览器本地存储；清除浏览器数据会丢失。存储被禁用/空间不足时明确显示“本次未保存”，不承诺可靠备份。
- 测试环境禁止 file/localhost 导航，因此通过 Playwright set_content 渲染完整 HTML。验证了存储拒绝提示，没有验证真实浏览器关闭再开启后的持久恢复。
- 没有连接或操作用户 Mac，没有更改主分支的运行时代码、签名或发布配置。

## 验证

`verify.py` 使用 Python Playwright 与 Chromium，运行真实鼠标拖动、触摸事件、点选替代操作、输入处理和下载。23 项检查的结果在 `verification.json`；其中模拟手机触摸不等于实体手机验收。

```sh
python verify.py
# 可通过 CHROMIUM_BIN 指定浏览器路径。
```

需要事先安装测试依赖，运行脚本不会自动安装软件。首次手感、视觉品质、社区规则与复杂工作流仍待评审，不用测试数量代替这些判断。
