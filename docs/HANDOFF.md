> 编写日期：2026-09-09。面向没有本次聊天上下文的开发模型。
> 本文档集是下一轮施工的规格与路线图，不是已实现功能清单。
> 核查的代码基线：`0914e18e85a7a402ee34ef5174aa2a30aa52f0e9`。
> 本轮只修改文档，不修代码、不发布 APK、不连接用户 Mac。

## 1. 用户究竟要什么

用户希望把成书做得非常好，明确要求“极致的用户体验和技术突破”。此前已经批准实施并合并了本地 EPUB、可靠保存与可恢复分享的 PR。用户不接受把“提了 PR”“做了测试”“留下补丁”说成“新版可以用了”。

用户最新要求是：把后续产品目标、开发方法、执行步骤与验收标准详细放进仓库，让能力一般、没有聊天记忆的模型也能接手。不要要求使用连接 Mac 的插件或应用。

最终体验目标：

> 在浏览器里发现想认真读的文章，分享给成书，之后在熟悉的阅读器里安心阅读。正常情况不用管格式、文件夹、任务队列和服务器；异常时知道内容有没有保存，以及下一步能做什么。

产品成功不以 App 停留时长、设置数量或支持格式数量衡量。先做到可安装、可升级、不丢结果，再做到快捷、内容可信和阅读舒适。

### 1.1 本文档集的权限和事实边界

- 用户目标是确定需求；本文档中的具体类名、任务拆分、指标预算和新数据模型是推荐执行方案，不是已经写好的代码。
- 当前任务只授权交付文档 PR。后续模型按自己的任务授权修改、提交、合并、发布，不能因为看到这份计划就自动改生产配置。
- 不要擅自更换正式包身份或签名、删除旧数据、引入第三方上传、购买服务或绕过访问控制。
- 用户不需要再提供产品方向；小的实现选择按本计划推进，只有真实的外部权限、签名迁移等不可自行决定事项才列为阻塞。
- 当前分支变化后先重新核对。这里的 SHA 是取证锚点，不是要求恢复到旧版本。

### 3.2 已有能力——先复用，不重做

1. Android 已能接收浏览器网址分享，通过 WebView 渲染并运行 Defuddle 提取正文。
2. Android EPUB 已走 `LocalEpub` 设备端打包；其他 Android 输出和网站转换仍走服务端。
3. `LocalArchive` 已有内容哈希文件、每篇清单、锁、原子清单更新、完整性校验和删除标记。
4. `Library` 已有旧存储懒迁移、正文快照、按格式保存、质量提醒和已有文件优先复用。
5. `PendingShares` 已先保存分享请求，未完成任务可从“最近”手动重试；进程内串行保护提取器。
6. EPUB 已有层级目录、部分锚点处理、图像预算与缺图提示，不再固定只取 12 张图。注意网站服务端仍保留 12 张上限，不能混为一谈。
7. 已有格式记忆、按格式选择应用、系统文件分享出口、预览版独立包名。
8. 已有真实子进程存储中断测试。必须保留，不要换成全 mock。

### 3.3 未完成或不能从现有证据推出的能力

- 没有 WorkManager 持久执行链。保存链接不等于系统杀进程后自动完成。
- WebView 依赖 Activity、主线程和页面生命周期；不能把现有提取函数直接塞进后台线程后宣称完成。
- 正文快照和各格式产物没有完整的显式版本关系，刷新、取消、重试的发布竞争需要补强。
- 图片尚未成为可恢复的独立持久资源缓存；重新打包不一定能完全离线。
- 部分列表读取、文件校验与共享复制发生在 UI 调用路径上，需要实测和移出主线程。
- 旧版覆盖安装、旧数据迁移、真实阅读器导入、深色/大字体、低内存与系统回收，未提供完整验收证据。
- 不能确认网站在机器人提交 APK 后必然部署成功；必须检查实际部署和公网下载。
- `android/debug.keystore` 在仓库中，正式/debug 构建使用这份 stable signing 配置。不能把它当成安全的长期正式签名方案；也不能随手换钥匙导致现有用户无法升级。
- `npm test`、`check:auth`、部分 preview scripts 引用基线缺失文件；先区分脚手架遗留问题，不要伪报全量门禁通过。

## 5. 下一位模型从哪里开始

### 第一步：核对，不修改

```sh
git status --short --branch
git diff --stat
git diff
git log -8 --oneline
git worktree list
```

这些命令在你自己的已授权工作环境执行；不是要求操作用户 Mac。若只有 GitHub API，读取默认分支、相关文件和最新运行，保留当前 SHA，创建任务分支。不要假设现成的本地目录。

### 第二步：先做 R01，而不是重写 App

复现空图片测试失败；修复源地址归一化时的空/空白值；补空 `src`、只有空格、空懒加载字段、合法相对地址、data URL 的断言。缺地址不得请求文章 URL，也不得被当作已嵌入图片。不得改掉正确的“1 张嵌入、2 张缺失”预期。

### 第三步：闭合首次可用版本

按 R02 → R03 → R04 → R05 执行。先保证构建、签名兼容、旧数据升级、下载地址和版本清单一致。**不要为了等整条路线图完成，拖延第一个经过验证的可用修复版；也不要为了赶发版跳过升级/内容门禁。**

### 第四步：再攻克真正的技术缺口

按 D 系列建立版本一致性和可恢复发布，再做 B 系列后台执行，之后做 U/Q/P 系列用户流程、阅读质量和性能。提取后台化有单独的有界实验任务，不能把它与普通文件打包混在一起。

## 7. 交接记录格式

每个 slice 至少留下：任务 ID；起止提交；改动范围；新增与既有测试；实际运行环境；产物和运行链接；已知限制；下一项及阻塞。没有运行写“未运行”，没有设备写“设备验收未完成”。

本轮文档的质量验收：路径存在、内部链接可达、任务依赖不循环、每个任务有测试和完成条件、当前失败没有被隐藏、未来能力没有冒充现状、文档 PR 不包含业务代码和 APK。
