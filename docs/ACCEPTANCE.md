# 成书验收规范：证明用户真的拿到了可靠结果

> 本文所有“应当”都是验收要求，不是本轮实测成绩。
> 任务步骤见 [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md)，交付操作见 [RELEASE_RUNBOOK.md](RELEASE_RUNBOOK.md)。

## 1. 证据分层，不能互相冒充

| 层级 | 能证明什么 | 不能证明什么 |
| --- | --- | --- |
| 源码断言 | 某个必要调用/配置存在 | UI 可点、生命周期、导入成功 |
| 纯 JVM/Node 单测 | 规则、序列化、确定性函数 | Android framework 真实行为 |
| 真实文件/子进程测试 | 写入中断、并发、损坏与恢复 | 真机包升级、系统调度 |
| Android instrumentation/模拟器 | Intent、数据库、权限、部分生命周期 | 所有厂商省电策略和真实阅读器 |
| 接收端测试 App | URI、MIME、授权和文件字节可读取 | WeRead/KOReader 的实际导入体验 |
| 真实设备 + 真实阅读器 | 用户路径、显示、兼容、升级 | 所有网站永远可用 |
| 公网下载与安装检查 | 发布产物确实到达用户路径 | 后续页面提取完整率 |

报告明确：命令、系统/设备、App/阅读器版本、源提交、产物 hash、测试时间、结果、日志/截图位置、限制。不得把旧提交测试移用到新提交。

## 3. 语料与测试环境

### 3.1 固定语料目录（拟新增）

建议 `tests/fixtures/articles/` 存储可再分发的原文片段、HTML/JSON、图片、预期 manifest；`tests/fixtures/legacy/` 存储人工生成的旧版数据；`tests/fixtures/network/` 存储可控服务器响应。

每份文章 manifest 最少记录：fixtureId、来源/许可、输入文件、基础 URL、预期标题、关键文本、目录目标、脚注连接、预期图片位置、禁止混入的导航/错误文案、合理降级、检查方法。大段真实第三方文章未经许可不要纳入仓库。

示例规格，不是已有 loader 接口：

```json
{
  "fixtureId": "footnotes-and-images-01",
  "license": "project-authored",
  "input": "article.html",
  "baseUrl": "https://example.test/articles/one",
  "expected": {
    "title": "测试文章",
    "headings": ["第一节", "第二节"],
    "imagePositions": 3,
    "missingImages": 1,
    "footnotePairs": 1,
    "forbiddenText": ["请登录后阅读全文"]
  }
}
```

`example.test` 等假域由测试 transport/本地服务器处理，不能要求真实外网解析才能跑。网络测试覆盖分块慢响应、错误 Content-Length、重定向、断连接与延时 DOM。

### 3.2 Android 矩阵

最低支持 API 26 必测；至少覆盖 API 30、33、34、35、36 的代表差异，并在执行时核对当前稳定 Android 版本补充测试。不能把未稳定预览版当成唯一验收环境。

主设备：一台普通 Android 手机；兼容设备：至少一台不同系统/厂商或低内存配置。模拟器可以完成自动化大部分场景，但真实阅读器与升级至少有真机证据。未获得设备权限时明确标为 BLOCKED，不能假设用户愿意替开发者测试所有东西。

记录浏览器与 Android System WebView 版本。真实 WeRead/KOReader 版本要记全，尤其两种 KOReader 包来源不能仅凭名称假定兼容。

## 5. 数据、版本与故障矩阵

| 编号 | 故障/操作 | 预期不变量 |
| --- | --- | --- |
| DATA-01 | 接收请求后、调度前中断 | 下次启动能补调度，链接不丢 |
| DATA-02 | 正文提交后中断 | 恢复复用 snapshot，不重新抓正文 |
| DATA-03 | 临时文件只写一半 | 不显示保存成功，不破坏旧文件 |
| DATA-04 | 完整 blob 已落盘、事务前中断 | 旧可读结果仍有效；孤儿文件可追踪 |
| DATA-05 | 发布事务后、UI 回调前中断 | 恢复返回相同 receipt，不重复生成 |
| DATA-06 | 两个执行者同时完成同代任务 | 只有一个权威提交结果，另一个复用/拒绝 |
| DATA-07 | 取消与发布并发 | 先取消则拒绝晚提交；先保存则保留文件 |
| DATA-08 | 删除文章后旧执行者返回 | tombstone/revision 阻止复活 |
| DATA-09 | 连续两次显式刷新 | 旧代不能覆盖新代；失败保留前一可读版 |
| DATA-10 | 新快照成功但新格式失败 | 旧产物标题/正文/警告不被新元数据冒充 |
| DATA-11 | 同文章多格式跨版本 | 每个 artifact 对应正确 snapshot 与设置 |
| DATA-12 | 200/1000 条保存记录 | 不因数量自动删旧文章，分页可用 |
| DATA-13 | 文件字节被破坏 | 检测损坏，不按非空文件宣布成功 |
| DATA-14 | 单条清单/数据库内容异常 | 坏条目隔离，其他内容可打开 |
| DATA-15 | 旧 index 与新清单重复迁移 | 幂等，无重复书，无删除项复活 |
| DATA-16 | 迁移中断/满盘 | 原数据不变，可继续迁移 |
| DATA-17 | URL 规范化版本变化 | 旧 ID 可寻址，不合并有业务区别的 URL |
| DATA-18 | GC 与保存/共享并行 | 不删仍被引用、发布中或刚交接的文件 |

并发测试采用显式屏障控制竞争点；不靠多运行几次“碰巧没复现”。故障注入只在测试/debug build，不能提供生产可调用的任意中断入口。

### 5.1 对事务提交的测试方法

在阶段标记处暂停执行，再由外部测试进程终止被测进程；重新启动后读真实数据库和文件，验证 record/receipt/hash。至少覆盖提交前和提交后两个窗口。

`ActivityScenario.recreate()` 只算页面重建，不算进程死亡。`am force-stop` 是用户强行停止语义，不与系统回收混用。物理断电恢复只有做过真实断电/文件系统证据才可声称，不由 `fsync` 代码存在推断。

## 6. 后台、权限与生命周期矩阵

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| LIFE-01 | 提取时转屏 | 请求保持，旧回调不会覆盖新 UI |
| LIFE-02 | snapshot 后退出页面 | 后续处理不依赖原 Activity |
| LIFE-03 | 后台完成 | 不抢前台，通知/最近能找到 |
| LIFE-04 | 系统回收进程 | 账本可恢复，已发布结果不重做 |
| LIFE-05 | 设备重启 | 系统允许后恢复可执行任务，不发虚假成功 |
| LIFE-06 | 用户 force-stop 后重开 | 重新对账；不承诺 force-stop 期间自动复活 |
| LIFE-07 | 通知权限拒绝 | 保存仍有效，首页能恢复，解释不过度打扰 |
| LIFE-08 | 前台任务收到停止/超时 | 释放资源并持久记录，不崩溃循环拉起 |
| LIFE-09 | 网络中断再恢复 | 有限退避，从 checkpoint 继续，不双发布 |
| LIFE-10 | 403/登录/验证码 | 不无限重试，不把登录框做成文章 |
| LIFE-11 | renderer 退出或 JS 无回调 | 有界结束并清理 WebView，任务可恢复 |
| LIFE-12 | 连续大量请求 | 并发有上限，后续任务不会永久饥饿 |

B04 未通过时 LIFE-02 的自动继续只覆盖“snapshot 已提交”的阶段。必须在报告显著写出，不用笼统的“后台测试通过”。

| 编号 | 语料 | 检查 |
| --- | --- | --- |
| BOOK-01 | EPUB 结构 | 首项 mimetype 未压缩；容器、OPF、NCX、spine 可解析；EPUBCheck 无错误 |
| BOOK-02 | 多层标题 | 目录层级合理，每项跳到真实标题 |
| BOOK-03 | 重复/中文/编码 ID | ID 唯一，脚注去回程真实可点 |
| BOOK-04 | 同页绝对链接 | 可正确转成本书跳转或明确保留外部原文 |
| BOOK-05 | 有起始序号的嵌套列表 | start/顺序/缩进语义未丢 |
| BOOK-06 | 表格与表头/跨格 | 内容关联可读；窄屏不无声裁切 |
| BOOK-07 | 长代码和 `<br>` 字面量 | 空格/换行保留，不误当 HTML 执行 |
| BOOK-08 | 中英、emoji、RTL 混合 | 无乱码/无效 XML，语言信息有合理降级 |
| BOOK-09 | 16 张图与重复资源 | 不受 12 张上限；资源去重但位置不删 |
| BOOK-10 | 空地址、404、403、超时 | 缺图数量、位置和摘要准确；无地址不请求正文 URL |
| BOOK-11 | 小压缩文件超大像素 | 解码前预算限制，不 OOM |
| BOOK-12 | 图片返回 HTML | 不冒充图像成功嵌入 |
| BOOK-13 | SVG/数学/交互媒体 | 支持则有正确证据，不支持有清楚降级提醒 |
| BOOK-14 | 刷新前后书籍身份 | 同快照身份稳定，新快照变化规则明确 |
| BOOK-15 | 已缓存资源后断网重打包 | 不再请求已有资源，能声明真实离线范围 |
| BOOK-16 | 浅深主题、字号变化 | 不锁白底黑字/字体，阅读器设置有效 |
| BOOK-17 | 登录页/导航页 | 质量规则识别异常，不正常成功 |
| BOOK-18 | 合法短文 | 不仅因短于某个长度就误报不可读 |

结构断言不能替代内容对照。每篇至少比较关键段落与禁止混入的文案，避免标题对了但正文是导航。

### 7.1 真实阅读器检查单

WeRead 与 KOReader 分别记录：导入入口；书名/作者；第一页；目录；一处脚注去程与回程；图文对应；表格；代码；字号；深色。同标题不同文章和同文更新各导入一次，观察目标阅读器是否错误合并。

目标阅读器不提供自动化回执时，可以由测试操作者确认并保存截图/录像；不能在生产 UI 中把测试人工确认变成“所有 Intent 成功都已导入”。

## 10. 网络、隐私与服务端负例

NET-01：正文、图片、JSON API 统一走受控请求器；对初始 URL、每跳重定向和实际连接地址验证。

NET-02：内网/回环/链路本地/IPv6/映射地址/DNS 变化由受控测试 transport 覆盖；不向真实未知目标发攻击式请求。

NET-03：请求体/响应流/图片/解码实际超预算立即结束，不等全量读入才检查。

NET-04：同前 120 字、不同后文的文本不缓存串书；同 HTML 不同 title/byline 结果正确；内存缓存有字节预算。

NET-05：Android EPUB 路径不 POST 正文到转换服务；其他格式按真实实现说明。接入新本地 serializer 后分别证明无上传。

NET-06：Cookie、认证头、正文、敏感 URL 不出现在日志、通知、诊断默认导出。Jina 等第三方行为符合明确策略。

NET-07：WebView 不对不可信网页暴露原生文件/命令桥；文件访问、跨源、TLS 错误处理采用明确受限配置。测试不通过时不能用忽略 SSL 错误绕过。

NET-08：备份导入拒绝路径穿越、ZIP bomb 和越界引用；失败不修改已有有效数据。

## 11. 性能预算：暂定目标，必须先建立基线

以下数字是工程起始预算，不是当前成绩、营销承诺或所有设备的 SLA。以固定参考设备、同样语料、同样网络、release-like 构建比较；调整预算必须写原因和产品影响。

| 指标 | 暂定目标 | 测量边界 |
| --- | --- | --- |
| 热启动分享接收确认 | p95 ≤ 300ms | Intent 到 durable job 提交/可见确认，不含网页读取 |
| 冷启动首个可操作界面 | p95 ≤ 1.5s | 同一参考设备，禁止等待全库迁移 |
| 既有 5MiB 文件打开请求 | p95 ≤ 1s | 点击到向系统请求打开；不含目标阅读器导入 |
| 1000 条记录首页摘要 | p95 ≤ 500ms | 首批分页，不包含生成全部行 |
| 无图标准正文设备打包 | p95 ≤ 2s | 已有 snapshot，固定大小与内核版本 |
| 大图/复杂文章 | 不 OOM/ANR；有预算截止 | 记录峰值内存、请求数、图片降级，不用单一秒数遮掩 |
| 连续 20 次任务 | 无持续增长的 Activity/WebView 泄漏 | 稳态 heap/native 内存和已结束实例 |

每组性能先预热，再至少 30 次测量，报告 p50/p95、失败数、最大值；网络部分单独统计，不把缓存命中和首次抓取混算。

主线程检查：开发构建 StrictMode、关键 trace；首页不得同步扫所有文件/做大 hash。不能通过减少正文或跳过图片伪造性能提升。

## 12. 发布门禁按承诺范围分层

### 12.1 文档 PR

检查 Markdown 链接、路径、任务 ID/依赖、事实锚点和差异范围。不得要求文档 PR 假装修好了基线 Android 失败；也不得为了文档通过去改业务测试。文档不自动发布 APK。

### 12.2 首次修复版 R05

必须：R01 修复与所有既有测试通过；APK 构建/验签；REL-01/02/06/08；新文章分享、已有文件复用、连续三篇、缺图提示、目标缺失、取消交接、旧数据迁移、WeRead/KOReader 核心检查。当前没有自动后台执行就明确限制，不必等待 B04 才发布，但不能声称已具备 B04。

### 12.3 新存储/后台版本

增加 DATA 全矩阵中受改动影响项，以及 LIFE-01 到 LIFE-12；接入迁移的版本必须通过多来源升级。单测成功但真实进程恢复未跑，不能发布为可靠后台版本。

### 12.4 新阅读质量/资源版本

增加 BOOK、NET 与性能相关项；必须检查真实阅读器和质量提醒，不仅检查 ZIP 有文件。

### 12.5 扩大分发前

长期签名方案、更新校验、隐私说明、服务端保护、备份/导出边界和真实失败恢复都要完成对应审查。签名或数据风险不能因为“只是小工具”忽略。

## 13. 证据文件约定（后续任务创建）

每次候选发布在 `docs/releases/` 留短验收记录，含 sourceCommit、versionCode、测试命令、设备/阅读器版本、artifact hash、Actions/Release/公网地址、已知限制。大日志、APK、截图作为 CI artifact/Release 附件，不把私人内容或大量二进制塞进 docs。

每项结果只能是 PASS、FAIL、BLOCKED、NOT_RUN 或 NOT_APPLICABLE。NOT_APPLICABLE 要解释与本次改动/承诺无关的原因；不能借它隐藏设备不可用。BLOCKED 和 NOT_RUN 都不等于 PASS。

## 14. 遇到红灯怎样处理

先保留失败证据和可复现输入；确定是基线问题、环境问题还是回归；最小修复后重跑失败项与相关门禁。不要在未定位时连续重跑直到碰巧绿。

真实外站偶发变化与固定 fixture 回归分开。外站不可达不能说本地算法坏，也不能拿本地 fixture 通过声称外站没问题。最终发布包必须是最终通过候选，不得在验证后再改一行代码却沿用原结果。
