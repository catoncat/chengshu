# 成书实施计划：按任务执行，不靠猜测推进

> 这是任务规格，不是进度。所有任务初始状态见 [STATUS.md](STATUS.md)。
> 全局行为见 [PRODUCT_SPEC.md](PRODUCT_SPEC.md)；架构约束见 [TECHNICAL_DESIGN.md](TECHNICAL_DESIGN.md)。

## 0. 每个任务的执行模板

1. 核对当前分支与代码；读指定文件及相关测试，确认问题仍存在。
2. 建立一个失败样例或记录基线。代码行为变更先写能失败的行为测试，不先写大重构。
3. 按本任务范围实现；新入口必须有真实调用方，不交付无人使用的工具类。
4. 跑本任务测试与受影响的既有门禁。真机、模拟器、源码断言分开记录。
5. 检查 diff、数据/隐私/签名边界；更新 STATUS，形成可独立审查提交。
6. 当前授权允许继续时进入下一项，不把“写完了一个类”当成停工理由。

任务未完成可以提交清晰的 WIP，但不能合并为正式可用能力、不能标记 DONE。工具/权限阻塞写明具体缺口，转做独立的已授权任务；不扩大到重构整个仓库。

### 全局不准做

不删除正确失败测试，不把预期改成错误实际值，不用 `-x test` 发布，不修改正式签名来省事，不清空用户数据，不用永久前台服务伪装恢复，不把原始错误和补丁扔给用户让他收尾。

## 2. R：首先让用户拿到可靠的新版本

### R01 — 修复空图片与缺图统计

**入口**：`LocalEpub.java` 的 build 图片地址预处理；`LocalEpubTest.java`。

**先复现**：运行 LocalEpubTest，确认 `failuresProduceVisiblePlaceholdersAndPersistentWarning` 仍出现 expected 1 / actual 2。失败消失则查当前修复，不重复修改。

**步骤**：选取 src/data-src/data-original 中第一个非空白候选；没有候选时保留图片位置用于缺图占位，但不得解析为页面地址。合法相对地址仍使用 base URL 解析；data URL 不误当相对地址。后续 fetch 只接受实际可请求来源。

**补测试**：无 src、空字符串、空格、所有懒加载字段空白、合法相对 URL、合法 data URL、混合成功/失败图片。记录 loader 收到的 URL，断言从未为无地址图片请求文章 URL。

**完成条件**：原失败断言不变且通过，全部 EPUB 测试通过，既有图像预算/去重测试不退化。

**不做**：此任务不顺手重写图片缓存、不加框架、不改页面 UX、不删除缺图提示。

### R02 — 可重复构建与有效测试入口

**入口**：Gradle 配置、`.github/workflows/android.yml`、`package.json`、scripts。

**步骤**：记录 Java/Gradle/AGP/SDK/Node 版本；保留已有正确门禁；检查 package scripts 引用的文件是否存在，区分失效脚手架入口和产品测试。为 Android 与网站转换测试提供真实可运行的明确命令。

基线无 Gradle Wrapper。可以新增经过校验且固定版本的 wrapper，或先保留 CI 固定 Gradle；不能下载随机 wrapper JAR。采用 wrapper 后同步所有文档和 CI，不留两套不一致版本。

新增“构建前检查”应报告缺环境，不静默下载不受控代码。网站构建不能在验证时意外执行生产数据库迁移；优先用已有 build:dev 或新增纯构建命令，确认环境目标。

**补测试**：验证脚本确实会因故意失败样例返回非零；`tee` 不能吞掉退出码。CI 上传测试报告与精确源代码，不仅留最后一行成功。

**完成条件**：干净的已授权环境能够按 README 命令复现 Android 测试与 APK 构建；网站相关测试入口有效；原先缺失脚本问题有清楚处理，不伪称 npm test 之前已全绿。

### R03 — 旧版覆盖升级与签名核验

**入口**：正式旧 APK、build.gradle.kts、Library/LocalArchive、Android 测试工程。

**步骤**：取得用户可下载的旧版，记录 versionCode、包名、证书、hash；在专用测试设备安装并通过正常 App 流程生成多格式旧文章、设置与待处理项；构建新的候选 APK，使用严格更高 versionCode；覆盖安装，不卸载、不清数据；比较旧文件 hash、列表、默认去向、重开与导出。

必须分别测旧 index.json 和当前 LocalArchive 存储来源。测试装错 preview 包不能算覆盖升级成功。旧系统与当前系统至少各一条真实升级路径。

基线使用仓库内 keystore，不能假装这是长期安全签名。记录风险与可行迁移；未经授权不更换签名。若无法满足正式发布安全/兼容条件，只交付明确标识的预览构建，不把它冒充 R05 正式完成。

**完成条件**：签名与包名兼容、versionCode 更高、真实覆盖安装成功、旧内容字节不变、偏好可用、失败迁移不丢数据。设备/官方阅读器不可用就是未完成证据项。

### R04 — 自动版本与完整发布流水线

**入口**：android workflow、构建版本读取、public/app.json、下载发布方式。

**分三种事件**：文档改动不发布；PR/开发分支只验证和生成 preview；main 上经过门禁的产品改动才生成正式候选并发布。显式手动发布也跑同样门禁，不能绕过测试。

**版本策略**：先用最小人工递增完成首次修复版，再把 versionCode 分配自动化。只有一个串行发布者，读取已发布记录并为新源提交分配严格更大的 code；同源提交重跑复用已有发布身份。不能只依赖会重置/分叉的 run_number，不能让两个作业分到同一个 code。

构建支持显式传入分配后的版本，不先发布 manifest 再构建。versionName 使用项目的人类可读版本；同名后续构建可加明确 build 后缀，更新比较只依赖 versionCode。保留旧 manifest 字段，新增 sourceCommit/hash/size/channel。

**产物策略**：产物有不可变版本路径与 hash，先验证并上传 APK，再更新 latest 清单与旧下载入口。记录源码 SHA、构建参数、测试和证书。已有更高版本发布后，旧运行不能覆盖 latest。

**部署策略**：不要把 `git push public/chengshu.apk` 当成公网发布。查清实际 hosting 入口；同工作流显式完成后续发布，或使用经核实可触发的既有部署机制。不要为“触发下一个 workflow”索取宽权限 token。

**补测试**：两个发布排队；同 source 重跑；测试失败不更新 latest；上传失败不更新清单；旧运行晚完成；版本/文件/hash 不一致；文档提交不误发；preview 不覆盖正式版。

**完成条件**：用测试发布目标完整演练成功与失败路径；正式发布仍需 R03 与 R05 验收。R04 不是“YAML 能解析”就完成。

### R05 — 发布第一个确实能用的修复版

**前置**：R03/R04 门禁与 [RELEASE_RUNBOOK.md](RELEASE_RUNBOOK.md)。

**步骤**：冻结候选提交；核对版本与旧版更高；跑全套受影响验证；生成/验签 APK；完成真实分享与阅读器检查；正式发布；从用户下载地址重新下载并验证 hash、包名、版本；旧 App 检查更新能看到它；覆盖安装复测旧文章。

写人能懂的更新说明：本地 EPUB、可靠保存、已修问题与仍有的后台限制，不宣传路线图中的未实现能力。

**完成条件**：用户拿到真实可安装的新 APK/下载入口，官网与更新清单一致，覆盖升级证据完备。只有 PR、artifact、补丁、测试报告均不算完成。

**失败时**：保持旧线上版本，记录确切阶段；不卸载用户旧 App，不把失败清单推上去。按 runbook 回退。

## 3. D：把数据与任务做成可恢复的系统

### D01 — 固定旧版/故障语料

**入口**：ArchiveProof、LibrarySnapshotTest、拟新增 `tests/fixtures/legacy/` 与 Android instrumentation 配置。

准备可再分发的旧数据样本：正常/同标题/多格式/中文 emoji/body.ext/坏 index/缺文件/删除标记。记录每份原始字节 hash、预期行为与生成方法。不得放用户私人文章。

先写当前行为测试和故障注入 helper：请求保存后中断、快照后中断、blob 后中断、清单/事务后回包前中断。生产构建不开放故障端点。

**完成条件**：每份语料对应断言；真实文件/进程测试仍有效；新 Android 数据测试不是靠 stub 默认值“通过”。这批测试是后续迁移的保护网。

### D02 — 事务元数据目录与无损迁移

**入口**：拟新增 ChengshuDb/ArticleRepository/BlobStore；Library、LocalArchive。

按 TECHNICAL_DESIGN 的最小 schema 创建版本化数据库，启用并验证外键和事务策略，建立文章、快照、产物、任务所需索引。先加只读适配，后逐篇导入，再切写路径。

每篇迁移原子标记；旧文件不删除；已迁移文章单一写入权威，不维持两套独立可写清单。损坏条目隔离，其他文章继续显示。所有 I/O 不在 UI 主线程。

**测试**：D01 全部旧数据、迁移中途 kill、重复启动、磁盘满、坏条目、删除标记、数据库 schema 升级。比较文件 hash 与可读性。

**完成条件**：旧文章无损打开，新写入只走新 repository，重启和部分失败可恢复。未迁移不假装已迁移。

**不做**：此任务不接后台、不改阅读样式、不删除 LocalArchive 测试。

### D03 — 快照版本、产物与提交凭据

**入口**：ArticleRepository、JobRepository、LocalEpub 调用适配、LibrarySnapshotTest。

引入 snapshotId 与 artifact 的对应关系；记录格式、设置、打包器版本、资源清单、hash。实现“文件写好后，artifact 引用 + receipt + job 保存成功同事务”。Worker 先查 receipt，重复处理返回既有结果。

**测试**：旧 EPUB + 新 Markdown 不混元数据；刷新抓到了新正文但打包失败，旧可读文件/标题/警告仍不变；同代重复提交得到相同 receipt；已提交但回包前 kill，恢复不重打包；写完 blob 未提交仅产生可清理孤儿。

**完成条件**：用户能解释每份文件来自哪次正文，所有发布窗口有真实故障证据。

### D04 — 取消、删除、刷新与 URL 身份

**入口**：任务事务方法、ArticleRepository、ShareFlow/输入解析、URL 规范化。

实现 generation + ownerToken + expected article revision 的提交校验；取消与删除递增版本并建立终态/tombstone。旧回调不能复活已删除文章，也不能覆盖新刷新。

请求去重只作用于未完成等价意图，终态后用户再次分享可打开旧文件或新建明确刷新。设置改动不改变在途请求。

URL 规范化采用保守 identityVersion；补 `%2F`、重复 query、`ref`/`si` 有业务意义、尾斜杠、hash 路由、大小写 host、短链等语料；保留旧 ID 别名，不改完 ID 就让老书失踪。

**完成条件**：用同步屏障稳定触发“取消/删除/新刷新与旧发布竞争”，结果确定；不要靠 sleep 碰运气。拒绝旧发布的断言在真实事务层成立。

## 4. B：后台与生命周期

### B01 — 从正文 checkpoint 继续

**入口**：拟新增 ConversionCoordinator/ConversionWorker；ShareActivity.packJob；JobRepository。

接入兼容当前工具链的固定 WorkManager 版本。先只承接 snapshot 已保存之后的图片/打包/发布。Job 先落库再 enqueue；unique work 只传 jobId；完整设置从持久状态读取。

UI 只观察状态；转屏、退出 Activity 不成为任务唯一主人。没有正文且需要可见 WebView 时进入 NEEDS_USER，不伪称后台已捕获。

**测试**：snapshot 后销毁 Activity、进程中断再启动、重复 enqueue、后台失败后恢复、已保存 receipt 不重复执行。

**完成条件**：真实 Android 中已有正文任务可按系统调度恢复且保存；所有“自动继续”文案与实现边界一致。

### B02 — 重启对账与进程恢复

**入口**：应用级启动协调、JobRepository、WorkManager 适配。

实现数据库 job 与调度记录对账：已保存无须重跑；可继续 job 丢了调度则补；失效 owner 不可继续写；停止状态有明确恢复方式。每次启动对账有界，不阻塞首页。

**测试**：请求提交/调度前 kill；执行中 kill；数据库提交/回调前 kill；设备重启；系统限制；用户 force-stop 后重开。前三者分别注入，不能只调用 ActivityScenario.recreate。

**完成条件**：没有丢任务、幽灵 RUNNING、重复成果或旧执行覆盖。报告区分系统回收与用户强行停止，不承诺 force-stop 后自动复活。

### B03 — 通知与网络等待

**入口**：AndroidManifest、通知 channel、任务状态观察、错误分类。

增加通知权限的合适时机、完成/失败聚合通知、取消动作、点通知定位 artifact/job。必要前台工作响应系统停止，配置正确类型和权限。

网络错误分类，断网待恢复；重试有限；403/登录/正文空不无限重试。通知拒绝时仍从首页恢复，不能拿权限当阻塞转换条件。

**测试**：权限允许/拒绝、后台完成不抢屏、并发三篇只合理聚合、点旧通知打开正确结果、取消中止资源请求、网络恢复不重复发布。

**完成条件**：产品状态、通知和数据库一致；不存在后台直接 startActivity 的补丁式“解决方案”。

### B04 — 动态提取的有界实验

**入口**：PageExtractor、Defuddle asset、拟新增 CaptureController。

先建立动态 DOM/延时加载/SPA/需要登录的本地 fixture；再实验主线程、非特定 Activity 所有权的 WebView 捕获；独立评估静态提取快路径。

记录是否渲染推进、超时是否清理、renderer 崩溃后回调、内存和生命周期行为。最多保留一条候选实现；实验失败必须产出清楚边界和可用 fallback，不无限尝试保活技巧。

**完成条件**：通过代表设备与语料才能升级产品承诺；否则明确完成“实验与降级决策”，保持 NEEDS_USER。不得把研究任务 DONE 等同于后台动态捕获已上线。

## 5. U：让日常使用只剩一次分享

### U01 — 首次示例与目的地优先

**入口**：ShareActivity 首屏/确认页、activity_share.xml、Apps、prefs。

按照 PRODUCT_SPEC 做示例/粘贴入口与去向选择。保留已有明确格式/目的地偏好；首次新用户推荐 EPUB，不强迫解释格式。示例走真实转换链，未安装阅读器时仍能导出。

**测试**：全新数据首次桌面打开、首次分享、无阅读器、只装一个/多个、记住与不记住、升级已有偏好、剪贴板未点不读取。

**完成条件**：第一次能完成真实保存与交接；之后普通文章不再强制多轮询问；“更改本次”不会暗改全局。

### U02 — 统一首页与任务状态

**入口**：首页与最近列表、repository 查询/观察；ShareActivity.refreshHistory。

设置下沉；首页突出需要注意和最近结果。用有限分页/按需加载，不一次创建全部 View。已保存与未完成明确区分，完成记录不重复出现两行，坏记录不拖垮整个列表。

**测试**：0/1/200/1000 条记录、混合失败/等待/已保存、标题超长、单条损坏、跨 Activity 状态变化、配置重建。

**完成条件**：用户不需要知道任务 ID 就能找到每篇；无主线程全库扫描/文件 hash；列表状态不依赖静态轮询猜测。

### U03 — 可执行错误、分享与导出

**入口**：showFailure/openSaved/openFileUnchecked/shareItem；ReaderHandoff；文件选择器。

将错误映射为明确动作；分开保存失败和打开失败。实现可见的 VIEW/SEND/保存文件出口；取消 chooser 不删结果。临时 URI 对应不可变 artifact，不按标题复用路径。

**测试**：目标卸载、拒绝打开、无可用应用、chooser 取消、接收端延迟读流、同标题文件、导出失败/取消/重名、旧 URI 与新版本并存。

**完成条件**：所有错误都能回到可继续状态；没有“先重新转换才能换应用”的要求；权限只授予所选文件。

### U04 — 主题、无障碍与交互细节

**入口**：主题/颜色 XML、动态 View 样式、页面布局、返回处理。

建立主题 token，跟随系统与手动覆盖；处理大字体、显示缩放、窗口 insets、键盘、TalkBack、至少 48dp 触控、长标题、减少动画。逐屏检查，不只改 theme parent。

**测试**：浅/深、字体 1.0/1.3/2.0、320dp 宽、横屏、系统返回/手势、键盘弹出、TalkBack 完成主流程、转屏不重跑任务。

**完成条件**：主按钮不被裁切，状态语义清楚，主题切换不丢请求，无闪白/重复弹窗等明显回归；截图与操作结果归档。

## 6. Q：让生成的书真正值得读

### Q01 — 固定阅读语料与标准验证

**入口**：LocalEpubTest、服务端 convert tests、e2e-chengshu；拟新增 `tests/fixtures/articles/`。

建立固定、许可清楚的 HTML/JSON/图片 fixture 与机器可读 manifest，覆盖文章/SPA/脚注/长代码/表格/图文教程/登录页/非 UTF-8/中英 emoji。每篇标定预期标题、段落、章节、图数、脚注关系和不可接受内容。

接入固定版本 EPUBCheck，保存标准错误。保留真实阅读器验收，不能把 EPUBCheck 当 UX oracle。线上站点巡检单独执行，避免网站波动污染确定性 PR 门禁。

**完成条件**：语料能离线复现，转换质量有对照，不再只判断“文件非空”。

### Q02 — 图片持久化与有界流水线

**入口**：EpubImages、LocalEpub.fetchImages、BlobStore、snapshot 资源表。

按设计增加资源清单与缓存；流式下载与 hash；明确总量/并发/像素/时长预算；复用已缓存资源；失败图单独重试。支持经过测试的 lazy/srcset；保留顺序、图注和缺图位置。

**测试**：16+ 图、重复图、无地址、403/慢响应、HTML 冒充图片、巨大尺寸/压缩小但解码大、取消、资源预算、进程中断、离线重打包、重定向与来源请求头。

**完成条件**：内存和请求数有界，取消真正终止网络，已保存资源不重复下载；缺图不被错误计成功。

### Q03 — 正文语义与阅读器排版

**入口**：LocalEpub HTML 清理/NCX/CSS、服务端 article-html/epub-pack。

逐项修目录层级、重复/中文 ID、同页绝对锚点、脚注回链、ol start、嵌套列表、table header/colspan、pre/code 空格、图注、blockquote、语言 metadata。选择清晰的保留/降级策略，不一律 flatten。

**测试**：每个语义有独立 fixture 与 XML/DOM 断言，运行 EPUBCheck，真实 WeRead/KOReader 检查目录跳转和关键页。字节可重现和稳定书籍身份分开测。

**完成条件**：标准错误不增加，核心语义能读能跳，阅读器字号/深浅色不被强制样式破坏。

### Q04 — 质量报告与异常提示

**入口**：提取结果模型、QualityEvaluator、artifact metadata、UI 警告。

把“错误字符串”升级成结构化质量报告，给每种规则 code、严重性、位置和版本。固定语料校准阈值；普通文章直接交付，疑似不完整才加提示。

轻微缺图不每次强制弹窗；确认状态按 artifact + warning fingerprint 记忆，不能全局永久关闭所有问题。新版本新问题重新提醒。

**测试**：登录页/验证码不是正常成功、正文短但合法文章不过度误报、缺图数量准确、提醒确认后重开不重复打断、新 warning 不被旧确认吞掉。

**完成条件**：报告与书内/详情一致，没有虚假的“全文完整度 100%”。

## 7. S：服务端、隐私与更新不能成为短板

### S01 — 服务端请求与缓存边界

**入口**：`src/lib/convert/ssrf.ts`、pipeline.server.ts、routes/export.ts。

先测试缓存碰撞：相同文本前 120 字但后文不同；相同 HTML 不同 title/byline。缓存 key 包含完整内容和所有输出相关参数；限制总内存而非只限制条数。

统一受控 fetch：URL/DNS/IP 校验、重定向逐跳检查、实际连接地址约束、输入/输出流式上限、超时、取消。正文、图片、JSON 接口不漏一条。第三方提取改为显式策略和准确说明。

**测试**：可控服务/DNS transport 模拟合法与拒绝路径，不探测真实内网；字节超过预算即时中止；Jina 默认策略可验证；错误不回显敏感数据。

**完成条件**：功能与安全负例都通过，网站与 Android 远端格式仍可用。不能只增强 hostname 正则后声称完全解决 SSRF。

### S02 — TXT/Markdown/HTML 本地输出

**入口**：拟新增本地 serializer、Format、下载路由选择；共享 fixture。

按 TXT → Markdown → sanitized HTML 顺序做，每种独立完成。输入是同一 snapshot；避免再联网提取；保留来源、段落、代码和必要链接。HTML 图片离线语义必须讲清：单文件内嵌与外链不能都叫“完整离线”。

**测试**：跨格式 snapshot 一致；断网生成；markdown escaping、嵌套列表、代码 fence、table 降级；HTML 活动内容清理；无正文上传请求。

**完成条件**：每种格式分别完成行为验证才更新隐私文案。PDF 继续走明确服务端路径，设备 PDF 另做收益评估，不为了“全本地”贸然重写。

### S03 — 更新下载与长期签名

**入口**：Update.java、installUpdate、发布清单、正式签名配置。

下载 manifest/APK 有大小与超时限制，来源校验、hash、包名、versionCode、channel、证书匹配；临时文件完成后才可安装；失败不影响旧 App。向后兼容清单字段。

对已公开的签名材料制定明确迁移决策：已安装用户、旧 Android 支持、合法 signing lineage/独立新安装选择、安全存储与恢复流程。密钥只由授权环境管理，不写进 PR/日志。此子任务涉及不可逆选择时停止该动作并列出所需决策，不自行替用户换钥匙。

**测试**：旧清单、新清单、错误 hash/包名/版本、重定向到不允许来源、下载半截、超大 APK、取消安装、权限拒绝、preview/stable 隔离。

**完成条件**：正常升级顺畅，错误候选绝不进入安装请求；签名风险有被实际执行/授权的处置，不能仅删除 keystore 文件宣称安全。

## 8. P：性能、占用与长期使用

### P01 — 主线程与资源基准

**入口**：首页、Library 查询/校验、复制交接、EpubImages、LocalEpub。

用 StrictMode/trace 与固定设备先测，不凭感觉优化。移出主线程 DB/文件读取、hash、大复制和迁移。分页最近列表，限制同时转换数和解码。减少全量 byte[] 重复持有。

**测试**：冷启动/热启动、已有文件打开、1000 条列表、大图文章连续 20 次、快网/弱网、低内存；报告 p50/p95 与峰值内存，不只给最快一次。

**完成条件**：符合 ACCEPTANCE 的暂定预算或有经过评审的新预算；无 OOM/ANR，减少的耗时没有通过少存内容换来。

### P02 — 垃圾回收与低空间

**入口**：BlobStore、事务引用、tombstone、迁移来源。

先实现 dry-run 统计 staging/无引用 blob/用户保存/旧迁移文件。再做标记清扫与宽限期；发布中的 pin 防止清理竞争。引用无法确认时停止，不猜测删除。

**测试**：GC 与保存并发、取消后晚到文件、旧版本仍引用、进程中断、坏数据库、满盘、重复执行。比较所有引用文件仍可读。

**完成条件**：释放空间有可解释来源，不自动清理用户保留文章，不复活删除条目，不删除接收端仍可能读取的刚共享文件。

### P03 — 导出/备份与恢复

**入口**：系统文件选择器、备份 manifest、ArticleRepository 导入。

先保证单文件导出完整；再实现可选完整备份包，包含版本、清单、hash、设置范围和恢复说明。导入先校验再逐项提交，不覆盖现有内容；重复内容按 hash 合并，冲突给明确规则。

**测试**：干净安装恢复、重复导入、半截包、错误 hash、路径穿越、ZIP bomb、重名、旧 schema、用户取消。

**完成条件**：用户不必理解数据库就能保留成果；导入失败不破坏已有文章。无需求不增加账号/云同步。

## 9. M：把改善交到用户手里

### M01 — 官网与说明

**入口**：index.tsx、en.tsx、site-header、README、下载入口。

按产品规格调整首屏；用真实产品演示替代口号；更新本地/联网处理边界和版本说明；保留现有中英文与主题。演示内容可再分发，不泄露私人页面。

**测试**：移动端窄屏/桌面、深浅色、中英链接、APK 下载类型/版本、更新清单、无效网络时说明。构建不能误触生产迁移。

**完成条件**：第一次访问能找到正确下载，说明与已发布能力一致。未上线能力不写成宣传卖点。

### M02 — 真实日常使用与最终验收

**入口**：全部产品主链、ACCEPTANCE、release evidence。

以一组真实使用任务连续完成：新文章分享、连续三篇、离线重开、缺图、长代码/脚注、切后台、重启、换阅读器、导出、升级。至少包含 WeRead 与 KOReader 的实际版本证据；不能只用接收端测试 app。

汇总阻塞问题，先修数据/错误交付，再修主流程，再修视觉。每个修复仍走测试和发布，不在最终阶段塞一堆无验证的小补丁。

**完成条件**：门禁表有来源清楚的结果，最终下载对应被测提交，用户能直接升级使用；未完成的 B04/P03 等后续能力明确不冒充完成。

## 10. 可并行与不宜并行的工作

可并行：固定语料/测试、官网说明、服务端安全、Android 独立模块；先约定接口和 fixture 格式。

不宜并行：多人同时改 ShareActivity、同一数据库 migration、正式发布版本分配、签名配置。同一工作区由一个负责人落盘；审阅者可只读。

每次整合先跑针对性测试再跑统一门禁。不能把不同分支的通过结果拼成一个没有实际构建过的“全绿版本”。

## 11. 阶段演示与交付物

- R 阶段：一个可下载且证明覆盖升级的 APK，不是补丁。
- D 阶段：一次在提交窗口真实 kill 后恢复的证明，旧成果不变。
- B 阶段：分享后离开，重开能准确找到结果；说明系统允许的自动继续边界。
- U 阶段：新用户从示例到阅读器，老用户普通分享无额外必答问题。
- Q 阶段：一本真实样本展示目录、脚注、图片和代码，附标准检查与阅读器证据。
- S/P 阶段：网络、更新、资源使用和长期数据可用性的可复現报告。
- M 阶段：用户安装的是这次实际验证过的版本，官网/清单/文件一致。
