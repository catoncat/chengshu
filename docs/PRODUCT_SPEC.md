# 成书产品规格：用户只需要说“这篇我想读”

> 状态：推荐的后续产品规格，不表示已全部实现。事实基线见 [HANDOFF.md](HANDOFF.md)，施工顺序见 [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md)。

## 1. 产品承诺

成书是浏览器与用户已有阅读环境之间的轻量工具。主路径：接收链接 → 得到可信内容 → 保存文件 → 交给用户选择的去向。

五个优先级，从高到低：

1. **不丢结果。** 失败、切应用、升级、取消打开，都不能无声弄丢已保存内容。
2. **不骗人。** 没拿到正文、缺了图、只发起打开，都要准确表达。
3. **少做决定。** 常用流程只需系统分享选择成书，之后不再问格式和去向。
4. **读起来好。** 目录、段落、脚注、表格、代码和图片顺序在真实阅读器里可用。
5. **用起来精致。** 大字体、深色、返回、单手、慢网、权限拒绝、错误恢复都自然。

出现冲突时按以上顺序取舍。不能为了少一次点击暗中上传内容，不能为了漂亮动画延迟已准备好的交接，不能为了“100% 成功”把错误页面做成书。

## 2. 做什么、不做什么

### 当前主线

Android 网址分享、EPUB 本地生成、已有格式兼容、目的地记忆、最近结果找回、失败恢复、安全升级。网站负责清楚介绍、下载、说明处理方式，以及维护既有网页版转换能力。

### 暂不做

社交、账号体系、云书库、多设备同步、内置完整阅读器、阅读打卡、AI 摘要强插入、复杂标签、插件市场、任意网页自动爬全站、批量付费内容抓取。

不是永久拒绝这些功能，而是在可靠交付、一键习惯和阅读质量通过验收前不投入。技术突破的价值必须对应一个用户感受，不能只对应一种新框架。

### 技术成果应怎样翻译成体验

| 技术成果 | 用户感受 |
| --- | --- |
| 保存有提交凭据，重试不重复发布 | 上次做完的不会再做一遍，失败也不会覆盖好文件 |
| 正文版本与图片资源可复用 | 断网仍能重开，换格式不用重新抓网页 |
| 执行不依赖某个页面一直活着 | 切走办别的事，回来知道结果在哪里 |
| 结构化质量报告 | 缺哪张图、哪里不完整说得明白 |
| 目的地与格式分离 | 我只选在哪里读，不必学 EPUB 是什么 |
| 发布产物有来源且可验证升级 | 点更新就得到新功能，不丢旧文章 |

## 3. 首次使用：一篇成功胜过三屏教程

### 3.1 第一次从桌面打开

标题：**把想认真读的网页，送进你的阅读器。**

主按钮：**试一篇文章**。次按钮：**粘贴链接**。一行说明：**以后在浏览器里点“分享 → 成书”即可。** 设置放右上角，不把格式、排除应用、版本号作为首页主体。

示例文章使用仓库内可再分发的固定内容，包含两个章节、一张小图、一条脚注和一小段代码。示例必须真的走产品打包与交接代码，不得播放动画冒充转换成功。示例标明“示例”，用户可以删除，不污染质量成功率统计。示例优先不依赖外网，便于新安装和测试稳定复现。

不要自动读取剪贴板。用户点击“粘贴链接”才读取并显示候选链接。无链接时告诉他支持什么，保留输入，不清空刚粘贴的文本。

### 3.2 第一次从浏览器分享

先接住并保存请求，再显示文章标题占位与来源。默认推荐 EPUB，但用户真正选择的是“打开阅读器 / 分享给其他应用 / 保存文件”。没有选择过阅读器时，在文件准备好后选择一次；不要在提取前强制做多轮设置。

当设备上能发现阅读器，显示实际名称与图标。不要展示未安装应用却让点击直接失败。没有阅读器仍能保存到文件或系统分享，不能成为 onboarding 死路。

“以后直接这样处理”默认选中与否须在 UI 实现时采用明确一致的行为；本计划默认**清晰可见、由用户主动选择记住**，不把一次试用目的地永久绑死。已有用户的明确偏好原样迁移。

### 3.3 首次权限

不在首次打开时一次请求通知、安装未知应用、存储等权限。需要通知时解释“处理完告诉你”，拒绝仍能完成并在最近找到。需要升级安装时才请求安装权限。文件保存优先系统文件选择器，不索取整个存储权限。

## 4. 熟练用户的主流程

### 4.1 新文章，已有常用去向

系统分享选择成书后，显示：文章标题、来源、**送往：微信读书 · 更改**、当前真实阶段。正常情况不再出现格式询问、应用选择、完成确认三连弹窗。

保存成功且用户仍主动停留在当前交接流程，才可尝试打开常用阅读器。用户已经切走，保持后台结果与通知，不抢前台。

“更改”只改当前请求；是否同步为以后的默认值由明确开关决定。请求开始后冻结本次输出配置，设置页的改动不应悄悄改变正在做的书。

### 4.2 重复分享

同一已保存文章的同格式：优先使用已保存结果，显示“已保存过，正在打开”。不因经过 45 秒、一天或一周就重新抓取。

目标格式尚未存在：有可用正文快照就基于该版本生成；没有快照才清楚说明需要重新读取网页。

同一个未完成请求再次进入：聚焦已有任务，不新增相同后台工作。用户明确点“更新原文”则是一个新版本请求，不与普通重复分享混淆。

### 4.3 连续分享多篇

每篇都能在最近/待处理列表看见。第一篇失败不能阻塞第二篇；第一篇需要用户登录时，后面不需要交互的任务可继续。不能让最后一篇替换前一篇的标题、选项或回调。

界面可以只显示“正在处理 1 篇，后面还有 2 篇”，点开才显示详情。不要暴露线程、Worker、数据库租约等内部概念。多篇完成时聚合通知，避免连响和连续打开阅读器。

## 5. 首页与信息层级

有内容后的首页分为三层：

1. 顶部：产品名、添加链接、设置；常用去向是一行摘要。
2. 需要注意：失败、等待网络、需要登录、保存后没打开等，仅在存在时展示。
3. 最近保存：标题、来源、保存时间、输出格式、质量提示的小标记。

点击已保存文章直接打开常用去向。长按菜单不是唯一出口；每行有可被无障碍识别的更多操作按钮。详情应提供打开、分享文件、保存到文件夹、更新原文、查看原文和删除。

“最近”不冒充备份。告知卸载应用会影响应用内数据；可导出文件。不要通过超过固定数量自动删除用户认为已经保存的内容。

记录按用户最近操作合理排序，但保留独立的“原文提取时间”“文件生成时间”“最近打开时间”。不能把最近打开时间显示为文章更新日期。

## 6. 状态与文案的唯一含义

| 用户看到的文字 | 必须真实发生了什么 | 可用操作 |
| --- | --- | --- |
| 链接已接住 | 请求已持久化成功 | 返回、取消处理 |
| 正在读取正文 | 当前真的在提取，不是等队列 | 返回、取消 |
| 等待网络 | 任务被明确识别为暂不可联网 | 稍后继续、重试 |
| 正文已保存，正在整理 | 正文快照已提交，可从这里恢复 | 返回、取消后续处理 |
| 文件已保存 | 文件完整性校验与发布记录完成 | 打开、分享、导出 |
| 已请求打开阅读器 | 系统调用成功返回，无导入回执 | 回最近、再次打开 |
| 文件已保存，但未能打开 | 保存成功、交接失败 | 换应用、分享、导出 |
| 需要在成书中继续读取 | 当前页面需要可见渲染或用户交互 | 继续读取、查看原文 |
| 可能不完整 | 命中已记录的质量规则 | 查看详情、保留、原文 |
| 本次没有保存成功 | 没有形成新可用文件 | 重试；已有旧版仍保留 |

禁止文案：未经证实的“已导入微信读书”“完整全文已保存”“后台一定会完成”；面向用户的原始 JSON、堆栈、HTTP 异常名、租约 ID。

进度只显示真实阶段。无法知道总工作量时用不定进度，不造 37%、83% 的假精度。等待超过短暂过渡后补充原因，不用永久转圈遮住错误。

## 7. 错误应该带来下一步，而不是让用户研究报错

### 网络中断

“网络暂时不可用，链接已保留。”已保存正文时改为“正文已保留，联网后继续处理图片”。网络恢复自动重试必须有次数和预算上限，不能无限重抓网页。

### 登录与付费页面

“目前没有拿到可阅读的正文。可以在成书中打开原文继续操作，或保留链接。”浏览器登录态与成书 WebView 不是同一份，不能说“你去 Chrome 登录一次就一定好了”。不绕过付费墙，不自动传浏览器 Cookie。

### 缺图与特殊内容

轻微提醒以不阻断的摘要呈现，例如“已保存，有 2 张图片未获取”。详情能定位缺失位置。疑似正文严重缺失、登录页等才进入明确确认/修复流程。

同一文件每次打开都重复弹同一个警告会造成疲劳：对同一 artifact + 同一 warning fingerprint，用户确认后记住已看过；新版本或新问题才再次提醒。警告在书内和详情仍保留。

### 空间不足或损坏

“空间不足，本次没有保存；之前的文件仍在。”不要自动清空全部缓存和旧数据。用户选择清理时列出类别、大小和影响。单篇记录损坏不能让整个最近列表消失；坏记录隔离显示并保留可恢复数据。

### 阅读器不存在或打开失败

直接给“选其他应用 / 分享文件 / 保存到文件夹”，不要求重新转换。取消系统选择器只是取消打开，不是删除文章，也不进入“转换失败”。

## 8. 文件打开、分享、导出分别设计

**打开阅读器**：ACTION_VIEW，使用已经保存的本地内容 URI。记住目的地时说明格式；应用更新/卸载后自动降级到重新选择，不永久报错。

**分享文件**：ACTION_SEND，调用系统分享面板，保留笔记、聊天、云盘等用户合理去向。首层推荐不等于硬性屏蔽。只给本文件临时读取权限。

**保存文件**：系统“创建文档”选择器，用户选目录/名称，复制已经校验的文件。完成前不能说导出成功。重名行为交给清楚的覆盖/改名选择，不能静默覆盖。

可考虑后续记忆用户授权的导出目录，但必须能失效恢复；没有授权就不能猜测一个 Downloads 路径强写。

## 9. 阅读结果规格

### 9.1 基础结构

标题只出现合理次数；作者和来源准确；标题层级形成可导航目录；脚注去程和回程可点击；列表起始序号、嵌套结构、表格表头、代码空格、正文链接必须保留语义。

不要把代码中的 `<br>` 文本当 HTML 换行，不要把文章标题清空后退成文件名 body，不要凭正文长度判断哪份一定正确。

### 9.2 图片

图片顺序、图注、替代文字和对应段落一致。去重的是资源字节，不是删除正文中重复出现的位置。缩小大图要保持比例和可读性；看不清的技术图不算成功优化。

缺图在原位置有占位，报告区分超时、403、格式不支持、过大、预算不足等原因。正常用户只看到摘要，开发者诊断才看细项。

### 9.3 阅读器自主权

默认使用阅读器字体、字号、深浅色与行距能力。不强制嵌入大字体文件，不把整本做成不可缩放图片。样式应克制，避免固定白底黑字、过宽表格、窄屏横向溢出。

PDF 定义为排版输出，不宣传成必然可重排。Markdown/纯文本是内容出口，不应擅自加营销段落。网页特殊媒体支持不完整时保留提醒与原文链接。

## 10. 精致感与可访问性

保留现有 Java/View 技术栈先做好体验。支持跟随系统主题；设置里可覆盖为浅色/深色。文字和背景用主题 token，不在动态 View 中散布固定颜色。

大字体和显示缩放下：主要按钮可见；底部操作不被遮挡；选择列表可滚动；两行以上长标题有完整访问方式；触控区域至少 48dp；文字不依赖颜色传达错误。

TalkBack 能按标题、状态、按钮、列表的顺序操作。状态变化适当播报但不在每个进度 tick 打断朗读。无图标按钮也应有清楚标签。

尊重系统减少动画设置；动效只解释状态变化，不阻塞打开。深色切换不重跑任务；旋转不重跑转换；返回不偷偷删除。

以上 48dp 等平台实践的实现参考：[Android accessibility](https://developer.android.com/guide/topics/ui/accessibility/apps)。验收以实际设备为准，不以 XML 里写过某个属性为准。

## 11. 隐私与透明度

界面按实际链路说明：Android EPUB 设备端生成；读取网页与图片会联网；其他格式在迁到本地之前要说明正文会发到转换服务。网站版本另行说明，不能沿用“全程本地”。

第三方提取兜底不能静默开启。诊断日志默认不包含文章正文、完整敏感 URL、Cookie、认证头和用户文件路径。用户导出诊断前能看见内容；不为了统计成功率增加默认追踪。

性能/质量统计先做本地开发基准。确需产品遥测时采用明确授权、最小化、可关闭方案，另做规格，不夹带进本轮 UX 实现。

## 12. 官网与更新体验

官网首屏要立即回答“能做什么、怎么试、怎么下载”：一句定位、Android 下载按钮、一段真实流程演示。平台要求、版本、更新说明和实际数据处理方式可找到；不是只有长篇创作动机。

下载成功不等于安装成功，安装成功不等于升级保留数据。App 显示真实可用新版本，不通过改 `app.json` 把尚不存在的 APK 宣传成可安装。

更新失败不损坏现有 App；用户拒绝安装权限或取消安装后能继续使用旧版。预览版与正式版不能互相覆盖或跨 channel 提示错误升级。

## 13. 产品指标：先测基线，再改进

建议指标而非既有成绩：首次成功交接所需额外决策次数；常用流程额外点击数；分享接收至保存的阶段耗时；重复打开耗时；失败恢复成功率；已知缺图被正确提示的比例；升级后旧文件完整性。

“已请求打开”单独统计，不能推断用户真的读了。提取成功率要固定语料、写明分母和被排除页面；不拿几篇手选文章宣传 99%。具体基准和预算见 [ACCEPTANCE.md](ACCEPTANCE.md)。

## 14. 每次产品评审的五个问题

这次改动是否让用户少做一件事？是否把失败变得可理解、可恢复？是否仍保留原来的正确结果？是否在真实阅读器里变好？用户是否真的能安装到这个变化？

答不出至少一项的新增复杂性，先不要做。
