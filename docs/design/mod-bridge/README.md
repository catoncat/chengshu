# 成书 · 造物桌

## 一句话

**把内容放进来，用几张能力卡，送到任何有用的地方。**

这不是把设置页画成卡牌，也不是把用户变成流程工程师。它是一张有手感的创造桌：东西可以拿起来、试着接上、看见变化，最后把好用的组合收进自己的口袋。

- [交互原型：prototype.html](prototype.html) — 保存后直接用浏览器打开；全部为示例，不安装插件、不读取私人文件、不联网转换。
- [完整体验与动效脚本](EXPERIENCE.md) — 页面、卡牌语法、组合规则、社区、异常、手机适配与设计验收。
- [验证与交付边界](VALIDATION.md) — 哪些已做、哪些只是设计、实际检查了什么。

> 2026-09-09 用户新命题：不局限网页到电子书；输入和输出由社区以游戏 Mod 的方式扩展；从组合与交互出发，不讨论插件技术架构。
> 本目录是设计探索，不是已上线的新版本。现有成书阅读能力成为其中一套配方，不必废弃。旧 PRODUCT_SPEC 把插件市场列为暂不做，是上一阶段的范围；本次新要求明确允许探索这一方向，但不自动授权改写生产 App、签名或发布方式。

## 1. 游戏设计师会先改什么

不是先改按钮形状，而是改“玩家在这里能做的动作”。

原来：选择格式 → 等待转换 → 打开文件。

新的动作循环：**拿到东西 → 看见可能 → 试配 → 看到结果 → 收成一张配方 → 下次直接用。**

游戏感来自可理解的规则、物体的连续性、组合产生的发现，以及成功后得到一个真实可用的东西。不是来自积分、宝箱、签到和闪光特效。

最重要的两层：

**日常层是工具：** 分享进来，点“做成阅读版”，就走。不要求每次摆牌。

**创造层是玩具：** 展开这张配方，换掉一张输出卡、加一张翻译卡，立即看见它变成另一种用途。

两层用“收起为一张卡 / 展开为一组卡”的空间变化连接。不是两个术语不通的产品。

## 2. 三种真正不同的方案

### A. 拼合牌桌 / The Workbench — 推荐作为主骨架

桌面上摆输入卡、可选的加工卡和去向卡。相容的卡口能吸附；卡口同时写内容名称，不仅靠颜色。原料沿牌桌向前走，用户可以在每一步看结果。

例子：

```text
[网页] ── [整理正文] ── [阅读器]
                         └─ 换成 [笔记本]：同一篇文章变成资料笔记

[截图] ── [识字] ── [整理清单] ── [笔记本]

[录音] ── [转成文字] ──┬─ [剪贴板]
                      └─ [保存文件]
```

不是强制三格。中间可以零张、一张或多张，末端也可以不止一个去处。“原文件直接保存”不需要为了凑齐三格硬加一张处理卡。

**代表手势：** 点卡加入、替换、前移/后移；拖放只是快捷方式；接近合法位置时先显示占位轮廓，放下才真正修改。手机优先点选，不让拇指跨屏拉线。

**性格：** 精密、温暖、可预测。像一套有质感的桌面工具，不像系统后台。

**优势：** 最容易解释输入输出和中间变化；容易撤销和修复；社区新卡能自然进入规则。

**风险：** 做成无限画布就会滑向流程编辑器。应限制默认展开密度，复杂段落收成子配方；用户看到“接下来做什么”，不看到端口参数和节点编号。

### B. 叠卡炼金 / Pocket Alchemy — 最有发现感

一张截图是一张原料卡。把“识字”叠上去，卡叠边缘露出文字；再放上“笔记本”，牌叠翻面，成为可打开的笔记。整套牌可以用纸封套收成“截图变笔记”。

**代表手势：** 两张卡靠近、试着搭配、松手成叠、侧滑展开每一步。不可组合时卡不消失、不扣任何东西，只轻轻分开并解释缺哪一张。

**性格：** 好奇、触觉、轻魔法。像把东西放在工作桌上，发现新用途。

**优势：** 单手、小屏、简单配方很有吸引力；“原料没有被消耗，结果多了一份”的反馈有成就感。

**风险：** 深牌叠隐藏步骤；复杂分支难懂；手势容易变成学习负担。运行真实任务不应靠扔卡的速度或准确性触发。

**采用方式：** 把它用于保存配方、试配和少步骤快捷操作，而不是把整个产品都做成叠卡解谜。

### C. 流转剧场 / Relay Stage — 最适合一份输入、多种成果

输入像一张小票进入舞台，经过几站，分成两束：一份去了笔记，另一份变成朗读。每一站都有正在发生的简短动作，完成成果落到各自的托盘里。

**代表手势：** 选择目的地、打开支路、聚焦一站。运行时路径自己显现，停下时收成一句话。不要求用户铺轨道。

**性格：** 有节奏、通透、偏仪器感。像看一场小型制作过程。

**优势：** 分支进度与部分失败非常清楚；适合展示“同一份内容生成多种东西”。

**风险：** 容易变成华而不实的流水线动画；路径多后变成交通图。输入输出只有两步时不值得占一整屏。

**采用方式：** 作为复杂配方的展开视图与运行反馈，不做新用户首页。

### 取舍

| 维度 | A 拼合牌桌 | B 叠卡炼金 | C 流转剧场 |
| --- | --- | --- | --- |
| 第一次理解 | 最直接 | 有惊喜，需试一次 | 需先理解站点 |
| 常用一两步 | 好 | 最轻巧 | 过重 |
| 多步骤编辑 | 最清楚 | 叠深了不清楚 | 较清楚 |
| 多输出与部分失败 | 可清楚呈现 | 不适合 | 最强 |
| 手机单手 | 点选很好 | 很有触感 | 需收拢 |
| 社区贡献规则 | 最容易统一 | 容易各做各的 | 易暴露复杂性 |

这些是设计判断，不是已经做过用户研究的结论。

**推荐：A 的结构 + B 的收卡仪式 + C 的结果反馈。** 原型重点验证这个组合，而非把三种风格各画一张没有行为的图。

## 3. 推荐方向的视觉世界

概念名：**造物桌**。它是成书的设计实验名，不是要求现在改 App 名。

主色是深墨绿，背景是暖纸色，输入/处理中使用薄荷和纸黄，去向使用陶土橙。色彩来自角色，不来自等级或稀有度。没有“金卡比普通卡更可靠”的暗示。

卡面有粗细不同的边框、规则编号、极简图形和一小段真实样例；留白大、字不挤。像现代纸牌与工业文具的结合，不是皮革纹理、金属铆钉和游戏 HUD 的堆叠。

卡面首先回答“它能做什么”，其次才是作者和版本。编号仅用于卡库识别，不作为实力数值。卡背是权限和行为说明，不是长设置表。

圆角、阴影、抬升都服务于可操作性：能拿起的有层次，固定的桌面不悬浮；当前落点有轮廓，非落点不无意义发光。小屏不使用扇形牌堆遮挡标题。

## 4. 三个空间，不是六个底部标签

### 口袋：直接做事

展示“我常用的配方”，不是把所有插件摊出来。第一张是“把文章带走”，第二张可能是“截图变笔记”。每张是完整动作，不是半成品能力。来自系统分享时已经知道原料，优先列出适合的配方。

一键使用，次级操作为“展开改一改”。没有内容时提供粘贴、文件、拍摄、录音等入口，但只展示可用的来源；不伪造已接入的系统能力。

### 造物桌：试出新组合

上方是原料，中间是配方，下方是此刻能接上的手牌。选一张卡之前能用样例预览它的作用。已搭配的流程始终能收起为一句话：“把截图里的文字存进笔记”。

只展开当前关注的一层。复杂配方可以作为一张“组合卡”被复用，但卡正面标出“内含 4 步 / 会上传文字”，不能借折叠藏起成本和风险。

### 工坊：发现别人的好办法

以“别人用它做成了什么”开场，不以插件包名开场。一个作品页同时展示前后样例、用到的卡、作者、适配版本、数据去向和成本。

操作顺序是“用示例试一下 → 查看所需能力 → 加入我的配方”。不是先装一堆依赖，再赌它能做什么。

社区卡和组合配方分开：能力作者提供积木，配方作者提供玩法。两者都署名；改编留下来源。没有抽卡、战力、签到、排行榜绑架。

## 5. 社区真正值得分享的是什么

至少有三种作品：

1. **能力卡**：一个新的输入、处理或去向，例如“从某个站点读文章”“整理成清单”“发到某个笔记应用”。
2. **配方卡**：把几种能力组合成实际用途，例如“开完会，纪要进笔记、待办进清单”。
3. **主题包**：卡面图案与轻动效。只能改变表达，不能隐藏权限标签、失败信息和操作出口。

一个 Mod 能带来新的动作，而不只是换皮肤。但无论社区做什么卡，四件事不能被自定义掉：当前处理的内容、真实去向、成本/权限、停止和找回结果。

“本地”不是荣誉徽章，“会联网”不是惩罚标记；它们是选择依据。外发文字、公开发布、扣费、改写文件等行为需要在合适时刻明确确认，而不是安装时一次性无限授权。

卡更新后权限增加时只暂停受影响的配方并说明变化。缺一张卡时保留配方轮廓，给替代卡建议；不要让收藏整体消失。用户作品和运行成果属于用户，不依赖作者一直维护。

## 6. 五个完整场景，证明它不再只是网页转换器

- **长文阅读**：网页 → 整理正文 → 阅读器。现有成书能力原样成为起手配方。
- **截图归档**：图片 → 识字 → 笔记。本次原型有样例路径，不宣称已接入 OCR。
- **录音整理**：声音 → 转成文字 → 整理清单 → 笔记/剪贴板。本次用固定示例，不录音。
- **不处理，直接转交**：文字 → 剪贴板，或图片 → 保存文件。证明中间加工不是强制角色。
- **一份变两份**：正文 → 笔记 + 文件。一个去向失败，另一个成果不消失；可以只重试失败的一支。

日历写入、群聊发送、公开发布等未来去向要有目的地预览与确认；不把“组合成功”误当成“获准对外执行”。

## 7. 这次交付什么，不交付什么

交付：三个方向的取舍、一套完整体验脚本、可离线打开的高保真交互原型、运行与恢复演示、社区试配、手机布局、浏览器验证记录。

不交付：正式 Android 改版、真实插件系统、真实 OCR/转写/翻译、阅读器连接、已存在的社区作者/安装量、正式网站部署。原型中的作者、模组和内容均明确为虚构示例。

不在这轮定 SDK、数据库、沙箱、API。下一轮先看原型是否让人“自然会用、愿意试新组合”，再决定实现，而不是提前让技术结构规定交互。

## 8. 看原型时，按这个顺序试

先在造物桌运行“把文章带走”；换成“截图变笔记”；试着接一张不相容的卡，看系统有没有讲清楚；加一个去向，打开故障演示，看成功成果是否保留；把配方收进口袋；最后到工坊试一套别人的配方。

不要只评价“卡片好不好看”。真正的问题是：不用学新术语能不能配出来？能不能预料一张新卡会带来什么？忙的时候能不能完全不摆牌？失败时有没有失去控制？

**最终希望用户的感受是：这是我的一小盒能力，我随时能用，也能把它组合成别人没替我预设过的用途。**
